# Engine bookkeeping and planning qualification

Removing a draft-only chat left its queued autosave entry behind. Releasing an orchestration lead also allowed an already pending worker read to restore the deleted lead's ownership. The [BEFORE log](engine-bookkeeping-before.log) records both failing assertions. The focused [AFTER log](engine-bookkeeping-after.log) records `draft_result=0` and `load_result=0` after the fixes.

Draft removal now clears the queued save, persisted fingerprint, and saved-user-block bookkeeping together. Lead release invalidates pending reads before they can publish stale ownership. The regression then reopens the released worker, preserves its transcript text, and checks that the fresh session and its blocks no longer point to the removed lead.

Missing worker models previously produced empty orchestration settings and still sent the planning turn to the lead provider. The actual Orchestration package over a controlled store reproduced that behavior in the [planning BEFORE log](orchestration-receipts/initial-before.log). The fix propagates discovery failure through the submit hooks. The [planning AFTER log](orchestration-receipts/worker-discovery-after.log) records the passing fixture. It checks that no provider send occurs, the exact discovery error reaches the caller, the visible proposal is invalid, the session is idle, and the failure callback runs once.

The final [engine suite](orchestration-receipts/engine-suite.log) passed 1,590 tests with no failures and four ignored tests. It includes all three regressions above and the saved-receipt compatibility tests. Strict workspace Clippy passed all targets and all features with `--locked`, `--offline`, and `-D warnings`. See the [Clippy log](orchestration-receipts/clippy.log) and [successful formatting and test summary](orchestration-receipts/summary.log).

The tests ran on arm64 macOS with Rust 1.98.1 in `~/Library/Caches/monocode-gpui-build/source`. Cargo compiled the established `--workspace --lib --bins --all-features --locked --offline -j 2` graph. The runner selected the engine test executable from Cargo's artifact JSON and ran its full suite. The [source snapshot](orchestration-receipts/engine-snapshot.json) records the executable SHA-256 and 297 engine and workspace file hashes. Every source hash matched the local checkout. These controlled tests do not claim a new live provider or GUI planning run.
