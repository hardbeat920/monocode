# OpenCode 2 qualification

The separate OpenCode 2 HTTP adapter passed one real, isolated smoke turn with the installed CLI version 2.0.20. Its private catalog reported ten enabled models. The test selected `opencode/fledge-alpha-free` only after checking that every advertised input, output, cache-read, and cache-write price was zero. The native adapter bound the provider session, streamed `pong`, received completion, and stopped its owned foreground server. The [live log](private-live.log) records one passing test in 3.61 seconds.

The first private run found eight enabled free models but failed before prompt admission. The server rejected `delivery: "steering"` with HTTP 400. The pinned protocol accepts `steer` or `queue`. The adapter now sends `steer`, and the real process, HTTP, and SSE fixture rejects any other delivery value. The [first log](private-live-first.log) preserves the failure. Only the successful retry admitted a model turn. No additional live turn ran.

## Source and startup

The implementation follows upstream release 2.0.20 at commit `84c9be93a56304a108f1a22df0c5d62c26d5b6ca`. Its [session protocol](https://github.com/anomalyco/opencode/blob/84c9be93a56304a108f1a22df0c5d62c26d5b6ca/packages/protocol/src/groups/session.ts), [event schema](https://github.com/anomalyco/opencode/blob/84c9be93a56304a108f1a22df0c5d62c26d5b6ca/packages/schema/src/session-event.ts), [form validation](https://github.com/anomalyco/opencode/blob/84c9be93a56304a108f1a22df0c5d62c26d5b6ca/packages/core/src/form.ts), and [OpenAPI](https://github.com/anomalyco/opencode/blob/84c9be93a56304a108f1a22df0c5d62c26d5b6ca/packages/protocol/openapi.json) define the contracts used by the fixtures. No new Rust dependency was added.

The public `OpenCodeAdapter` selects a protocol major once per resolved binary path. Version 1 keeps its existing implementation. Version 2 uses structured catalog requests, location-aware sessions, Basic authentication, forms, durable log recovery, and explicit provider-session resume. Unknown major versions fail before startup. The process API retains `harness_spawn` and adds `harness_spawn_with_env` for scoped OpenCode overrides. The shared app and headless child backend already delegate through that API.

Production starts its own `serve --stdio` process over the normal CLI profile. It addresses only explicitly created or bound provider sessions. The pinned [server process](https://github.com/anomalyco/opencode/blob/84c9be93a56304a108f1a22df0c5d62c26d5b6ca/packages/server/src/process.ts) resumes suspended sessions automatically only with the managed service lifecycle. The foreground process therefore preserves the user's existing provider database without installing a service, copying credentials, or resuming unrelated sessions.

For qualification, the existing local Mach-O arm64 executable was copied into the owned hometop task tools directory. It reported `opencode v2.0.20`. Both copies have SHA-256 `da6c61cd188189a0bd44450ae3e19cb654a958f0b1615c83ebe47a48d0b519ae`. The [staging log](staged-cli.log) records architecture, version, and hashes. This changed no global installation or PATH.

The [runner](run-private-live.py) removes known provider credential variables and inherited OpenCode overrides by name before launching the owned test process. It never reads or prints their values. The test creates private data, config, cache, state, and temporary directories, disables project configuration, supplies empty owned configuration, and uses an explicit binary path. It copies no account file. Its private server password never appears in request or spawn debug output. The scratch directories are removed, and a read-only process check found no remaining owned OpenCode server. No production profile, service, sign-in, permission, or project changed.

## Automated checks

The first [provider fixture run](fixtures.log) passed 114 tests with no failures and three ignored live tests. The [final run](final-fixtures.log) passed 116 tests, all 84 existing version 1 tests, two major-dispatch fixtures, and 30 version 2 fixtures. It retained three ignored live tests. The actual transport test runs through the native process backend, real authenticated loopback HTTP, and real SSE. It verifies the child-specific data path and prompt permission shape. Fake transport fixtures cover explicit resume and rewind, child approvals, repeated UI clicks, typed conditional questions, authoritative invalid-answer retries, hidden defaults, optional omissions, cancellation, compaction, and text-prompt cleanup.

Failure fixtures verify readiness URL rejection, startup timeout, early child exit, failed initial log loading, failed reconnect cleanup, and malformed attachment rejection before a turn starts. Forgetting a loaded session before its first turn clears both adapters' resume maps. The [environment test](environment.log) rejects non-OpenCode overrides, unsupported names, and NUL values. The [strict Clippy run](clippy.log) passed all targets and all features for the harness and process crates with `--locked` and `-D warnings`.

The live run used `target/debug/deps/monocode_harness-d4e9db6801135b23` in `~/Library/Caches/monocode-gpui-build/source`. The [live source and executable hashes](live-source-hashes.log) identify that compiled snapshot and compiler. Two final retained-behavior fixtures also passed for changed steering model, variant, and agent selection, idle steering rejection, and catalog context capacity. The [final environment test](final-environment.log) passed, and the later [strict workspace Clippy run](final-clippy.log) passed all targets and all features. The [current source manifest](source-sha256.json) records all 29 scoped source files, including the final Unix provider guard. Every hash matched the qualified hometop source. No additional live call ran for those changes.

These checks qualify the protocol and one anonymous free-model turn. They do not prove authenticated paid-provider use through OpenCode 2, a native GUI OpenCode conversation, a live resume from a second process, or the final Windows and Linux adapter snapshots. The mocked resume and recovery tests remain separate evidence.
