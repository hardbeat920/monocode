# Saved orchestration receipt compatibility

The retained orchestrator signs control requests with `JSON.stringify`. A saved approval receipt with request ID `7` rejected the unchanged native input `7.0` after hydration. The [initial BEFORE log](initial-before.log) records that failure. The actual approval command accepts that input, so the test exercises a valid control request.

The same run corrected an assumption in the old engine notes. GPUI enables `serde_json/preserve_order` transitively in the qualified workspace graph. The original TypeScript object-order fixture passed and kept its exact saved signature. There was no reproduced sorting failure in that graph. A second fixture constructs the same input fields in sorted order. The [bounded BEFORE log](before.log) records both retries failing with `Request ID was already used with different input`.

The fix compares exact signature strings first. Only a saved receipt with a different string uses the parsed comparison. It ignores object field order and treats equal decimal values such as `7` and `7.0` as equal. Raw number digits and checked exponents preserve changed fractional values and large integers without any floating-point conversion. It preserves array order, value types, and changed field values. Corrupt JSON and overflowing normalized exponents fail closed unless the original signature strings match. Existing pending requests still use their original exact signature comparison.

The hydrated delegation fixture checks that the retry returns its saved result without another worker, dispatch, scope resolution, or provider submission. It also checks that the original signature remains unchanged and a changed prompt still fails. The approval fixture checks that the unchanged retry does not answer twice and a changed request ID fails. Pure comparison tests cover nested objects, arrays, strings, booleans, corrupt receipts, fractional changes, and integers outside JavaScript's safe range.

The first implementation parsed ordinary JSON numbers. Its boundary test caught parser rounding at JavaScript's largest safe integer. The [first AFTER log](first-after.log) records that failure. The corrected comparison uses `RawValue` and exact decimal normalization. The engine now declares the `raw_value` feature directly. That feature already existed in the qualified dependency graph, so no package version or lockfile changed.

The final [hydration fixtures](after.log) passed both tests. All four [pure comparison tests](pure.log) passed, including decimal and exponent forms, negative values, changed fractional values, large integers, and exponent overflow. The [full engine suite](engine-suite.log) passed 1,590 tests with no failures and four ignored tests. Strict workspace Clippy passed all targets and all features with `--locked`, `--offline`, and `-D warnings`, recorded in the [Clippy log](clippy.log). The [summary](summary.log) records a successful whole-workspace formatting check too.

These checks used the established workspace feature graph on the isolated arm64 macOS build host with Rust 1.98.1. The [engine snapshot](engine-snapshot.json) records every engine file, workspace manifests, and the compiled test executable hash. All 297 engine and workspace file hashes matched the local checkout. The [receipt manifest](source-sha256.json) records the four owned files. This comparison change does not alter serialization or the separate M0 database byte checks.
