# MonoCode can preserve history across providers

Extend MonoCode's existing provider-switch handoff with durable per-provider bindings, exact portable history, delivery receipts, and target capability checks. T3 Code's latest nightly observed on October 3, 2026 is `v0.0.46-nightly.20261003.2623`, commit `fed41fa88bb27cb4325cb208d571393850bc63c2`. Its new orchestrator keeps one application conversation while switching between separate provider-native conversations. Cross-provider "full context" means budgeted selected visible history, with omissions and retrieval references. It cannot transfer private reasoning or native tool state between vendors. MonoCode already has the picker and handoff flow to build on. The missing work is durable switching and richer context delivery, followed by host protocol support. [Nightly release](https://github.com/pingdotgg/t3code/releases/tag/v0.0.46-nightly.20261003.2623), [portable handoff guide](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/docs/user/portable-handoffs.md#L3-L18).

## T3 keeps the conversation above each provider

Orchestrator V2 is the production server implementation in this nightly. The application thread owns persisted history. Each run records its provider instance, model selection, provider thread, and handoff. A provider thread identifies that provider's native conversation, independently of its live process. Changing the composer selection therefore does not rename earlier turns or replace the application thread. [Production wiring](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/server.ts#L445-L462), [run provenance](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/Orchestrator.ts#L5657-L5735).

First use of provider B creates its native conversation and prepares eligible application history before B's turn. Returning from B to A selects A's existing root provider thread and transfers the interval after A's last delivered run. Completed, failed, and interrupted runs can contribute context. Failed or interrupted runs advance A's delivery boundary only when a provider-turn record proves delivery. Ordinary switch selection excludes queued, cancelled, and rolled-back runs. This distinction prevents failed starts from making A appear current. [Target selection and coverage](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/Orchestrator.ts#L5262-L5492), [delivery boundary](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/Orchestrator.ts#L660-L676).

Normal switching applies between turns. A new request during an active run queues with its requested selection. Dispatch later recalculates the handoff through the latest settled history. Explicit steering or restart uses a separate interrupt policy. Same-provider model changes use adapter rules for native continuation, restart, or rejection. These rules depend on provider capabilities. Replacing a Claude query with background work can be blocked because it would terminate that work. [Scheduling policy](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/CommandPolicy.ts#L389-L479), [transition policy](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/ProviderSessionTransitionPolicy.ts#L34-L95), [Claude continuation gate](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts#L6835-L6898).

Delivery records the actual native thread identity and item IDs. It persists `pending` before import, then `injected` after native success or `inline` after the target accepts an inline turn. Duplicate IDs disappear before delivery. A lost acknowledgement leaves the native thread ambiguous. T3 abandons that native identity and creates a fresh conversation with full portable fallback history, as it also does after failed native resume. This avoids importing the same history twice into an uncertain conversation. It does not establish universal exactly-once execution by provider APIs. [Delivery protocol](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/ContextHandoffDelivery.ts#L23-L140), [fresh-thread recovery](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/ProviderTurnStartService.ts#L659-L732).

## Portable context preserves selected evidence

T3's portable items have user or assistant roles, complete selected text, source thread/run/item IDs, provider-thread identity, and status. The converter includes command input, exit code and recorded output, errors, interruption messages, file-change names, and proposed plans. File changes contain names, not patches. Reasoning, generic or dynamic tool/MCP payloads, native approval state, checkpoints, subagent objects, and historical attachments do not transfer through this representation. Recorded command output is the qualification to the release warning about omitted tool results. The strategy name `full_thread_summary` does not mean an LLM writes a summary. The implementation renders selected intact items. [History contract](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/packages/contracts/src/orchestrationV2.ts#L844-L895), [conversion](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/ContextHandoffBudget.ts#L140-L181), [preparation](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/ContextHandoffService.ts#L410-L485).

Only Codex implements native history injection in this snapshot. It calls `thread/inject_items` with historical user and assistant messages before the current turn. Method-not-found permits inline fallback. Other injection failures fail delivery because mutation could already have occurred. Claude, Pi, OpenCode 2, ACP, and Cursor receive attributed historical text in an outgoing user prompt, followed by a separate current-request section. Their native role structure therefore differs from Codex's imported messages. The application saves the original request once, without adding the synthetic history prompt as another user-authored turn. [Codex import](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/Adapters/CodexAdapterV2.ts#L5503-L5550), [shared prompt delivery](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/ProviderTurnStartService.ts#L1166-L1189).

The default history allowance is 16,000, capped at 64,000 bytes and constrained by remaining target capacity. Accounting conservatively charges UTF-8 bytes, JSON escaping, and wrappers rather than using a provider tokenizer. Capacity reserves existing native occupancy, the current request, attachments, and at least 16,000 or one quarter of the window for later work. Selection prioritizes the latest user item, latest assistant item, and original user item, then newer history. Items remain whole and retain chronological order. Oversized items can disappear entirely. The current request remains intact. Retrieval references point to omitted saved history, but availability depends on target tool integration. [Budget and selection](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/ContextHandoffBudget.ts#L94-L138), [selection and retrieval](https://github.com/pingdotgg/t3code/blob/fed41fa88bb27cb4325cb208d571393850bc63c2/apps/server/src/orchestration-v2/ContextHandoffBudget.ts#L227-L281).

The engineering lesson is to separate retained application history, delivered context, and provider-native continuation. Stored history alone does not prove the target saw it. Private model reasoning, native compaction state, and running tools cannot become another vendor's equivalent internal state.

## MonoCode already has the switching entry point

The reviewed checkout is `b585761aafb39c265618191897c5579fe509ccd2` plus substantial native Rust and remote work in progress. The native picker sends `ComposerEvent::ModelChange` to `Submit::set_model`. `PendingHarnessSwitch` retains the source binding while the selected provider changes. The session ID and transcript survive, and selecting the source again before sending restores its native binding. Same-provider model changes already use native continuation. [Picker wiring](/Users/gianvillarini/Documents/Github/monocode/apps/monocode-app/src/session_pane.rs:407), [switch planner](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/submit/handoff.rs:60), [pending source binding](/Users/gianvillarini/Documents/Github/monocode/crates/core/src/session.rs:60).

Cross-provider sends currently ask the source for a short recap or use a deterministic fallback, then forget the source and prepend the recap to the target prompt. The fallback has a soft 1,800-character budget, two shortened user messages, and selected recent activity. This loses far more visible history than T3's portable selection. Persistence omits `pending_switch`, so a picker-only switch lacks durable source recovery. Remote configuration fixes the provider once the session exists. [Recap limits](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/submit/handoff.rs:22), [handoff execution](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/submit/pipeline/turn.rs:372), [session persistence](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/runtime/session_store.rs:178), [remote restriction](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/remote/remote_session.rs:50).

Extend this flow. Keep `Session.blocks` and the shared SQLite store. Keep the separate multiagent orchestrator. Preserve ongoing native migration work and existing TypeScript/Node compatibility. The following phases are proposed changes, not implemented behavior.

## Six phases add continuity without replacing orchestration

### Phase 1. Persist bindings and switch intent

Extend `PendingHarnessSwitch` with a versioned durable switch record. Add per-provider bindings keyed by provider/account/environment/cwd identity, with native ID, generation, and last delivered transcript boundary. Store selected target separately from active binding. Record switch ID, source/target selection, frozen revision, delivery mode, included/omitted item IDs, and accepted-turn receipt. Give portable items stable IDs and actual turn provider/model provenance. Persist picker intent and switch state immediately before process changes. Update SQLite migration, sanitizer, reload, and fingerprint together. Old sessions seed one binding from their existing native ID. Missing fields retain old behavior, and legacy `provider_session_id` remains the active-binding view. [Core session](/Users/gianvillarini/Documents/Github/monocode/crates/core/src/session.rs:123), [shared store](/Users/gianvillarini/Documents/Github/monocode/crates/store/src/session_store.rs:1080), [reload](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/runtime/session_store.rs:1095).

### Phase 2. Export exact history with an omission manifest

Add a pure exporter under `crates/engine/src/submit` that reads settled `Session.blocks`. Include submitted messages and completed visible activity, preserving source IDs, ordering, and text. Exclude drafts, future queued requests, private reasoning, and live approval/question handles. Historical commands are evidence, never executable tool replay. Freeze a settled boundary and budget against the selected model after native occupancy, instructions, current input, attachments, and response allowance. Retain all source blocks regardless of omission. Add host-readable retrieval for omitted items. Keep the short recap as an explicit fallback. Preserve attachment descriptors and snapshot referenced bytes into durable storage when needed, with hashes and host identity. Resolve historical image delivery only when the adapter/model supports it, and disclose missing files or unsupported content. [Block content](/Users/gianvillarini/Documents/Github/monocode/crates/core/src/block.rs:512), [attachment persistence](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/runtime/session_store.rs:474), [attachment IO](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/submit/attachments.rs:31).

### Phase 3. Negotiate native import and preserve switchback

Add `ContextTransferCapabilities` and preparation/import methods to the existing `HarnessAdapter`. Capabilities describe supported roles, append-to-resumed-thread behavior, attachments, limits, receipts, and installed protocol version. First verify Codex and Claude import capabilities against their installed protocols. Use native role import only with evidence. Otherwise deliver delimited attributed history alongside a separate current request. Avoid invented native database or JSONL edits. A to B to A resumes A with only its missing interval when safe append is supported. Otherwise start fresh A with full eligible portable history. Same-provider model changes keep native state and apply provider-specific restart or rejection rules. [Adapter contract](/Users/gianvillarini/Documents/Github/monocode/crates/harness/src/core/registry.rs:154), [Codex continuation](/Users/gianvillarini/Documents/Github/monocode/crates/harness/src/providers/codex/session.rs:828), [Claude continuation](/Users/gianvillarini/Documents/Github/monocode/crates/harness/src/providers/claude/session.rs:2210).

### Phase 4. Make delivery recoverable across failures

Serialize switching through the existing logical-session queue. Default to applying the selection after the active turn settles. An explicit interrupt must cancel, drain final events, invalidate old generation callbacks, and freeze the resulting history. Block process replacement while background work cannot stop safely. Preserve the source through `stop_session`, then commit the active target only after its turn is accepted. Authentication, startup, and import failures retain a retryable source and request. Persist pending delivery before transport, then its receipt. Use provider idempotency where supported. Otherwise an ambiguous acknowledgement requires a fresh target identity with full portable fallback, never blind reinjection. Guard binding/config events with generation checks, and distinguish imported history from an accepted current request. Recover failed native resume with history rather than an empty session. [Turn generation](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/submit/pipeline/turn.rs:255), [stop flow](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/submit/pipeline/actions.rs:493), [binding reducer](/Users/gianvillarini/Documents/Github/monocode/crates/core/src/reducer/apply.rs:309).

### Phase 5. Execute remote switching on its owning host

Add a capability-gated `switchProvider` command carrying command ID, target selection, expected host revision, and transfer policy. The host exports history, resolves attachments, and performs delivery. Preserve persistent outbox deduplication and command receipts. Advertise `sessionProviderSwitchV1` before enabling the client action. Extend Rust host, Node host, Rust/TypeScript protocol declarations, sync metadata, and legacy remote client together. Add a source-preserving host stop operation because its current stop forgets native state. Carry account identity when binding. Reject unsupported commands on old hosts while model-only configuration continues. Initial scope keeps sessions on the same owning host. Cross-host moves require separate file transfer and path mapping. [Protocol](/Users/gianvillarini/Documents/Github/monocode/crates/remote/src/host/protocol.rs:456), [host provider wrapper](/Users/gianvillarini/Documents/Github/monocode/crates/host/src/providers.rs:126), [Node configure](/Users/gianvillarini/Documents/Github/monocode/host/engine.ts:465), [legacy remote client](/Users/gianvillarini/Documents/Github/monocode/src/features/connections/ui/RemoteSession.tsx:730).

### Phase 6. Expose transfer status in the existing UI

Keep `ModelChange` as the entry point. Show the next selected model separately from the running turn's provider. Reuse the handoff row for preparing, importing, accepted, failed, retry, and cancel states. Show transferred versus omitted context and distinguish native continuation, native import, attributed history, and recap fallback. Preserve each turn's original provider/model label. Connect the supported remote picker routes after host capability support ships. Use "Continue with shared history" with a transfer detail view. An unconditional "full context" label would misstate the defined behavior. [Native picker](/Users/gianvillarini/Documents/Github/monocode/apps/monocode-app/src/session_pane.rs:407), [turn provenance](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/runtime/session_store.rs:355).

## Validation must prove both fidelity and recovery

Start with focused core/store/submit/provider/host suites. Store fixtures must load old records and survive restart immediately after selection, after source stop, after import, and after target acceptance. Export fixtures must assert exact ordered long messages, command output, plans, errors, file activity, Unicode integrity, attachment references, exclusions, and whole-item budget loss. The current request must appear once. No imported activity may execute as a tool call. Extend the existing switch regression rather than accepting transcript persistence as delivery proof. [Existing engine test](/Users/gianvillarini/Documents/Github/monocode/crates/engine/src/submit/pipeline/tests.rs:755).

Fake-provider tests must cover native and inline delivery, both provider directions, A to B to A delta, stale native resume, target authentication failure, import failure before and after mutation, lost acknowledgements, failed turn acceptance after successful import, duplicate send, cancellation during import, active approval, late source events, background work, and rapid A to B to C or revert. Assert one logical session/worktree, accurate turn labels, a recoverable source, and no repeated current request. Remote tests must cover expected-revision rejection, command deduplication, disconnect/outbox replay, host attachment resolution, old-host capability rejection, and Rust/Node parity.

Release gates should progress through local inline handoff, verified native imports, remote host support, and client enablement. Require real Codex to Claude, Claude to Codex, and switchback conversations containing an early unique instruction and an attachment fact. Verify continuation in the same worktree, model-only native resume, restart recovery, and disclosed budget or attachment loss. Validate a real capable remote host before enabling remote switching.
