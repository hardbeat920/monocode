# Translations

MonoCode ships in English and Turkish. The language is chosen in Settings, and the default follows the system language.

## How it works

- `src/shared/i18n/catalog/` holds the messages, one file per feature area. Each file exports `en` (the source) and `tr`.
- `tr` is typed as `Translations<typeof en>`, so a Turkish message is missing or has a different shape, `tsc` fails.
- In components, call `const t = useT()` and then `t("inbox.empty")`. The component re-renders when the language changes.
- Outside React, call `t` from `shared/i18n/locale`. It always returns the current language, but it does not trigger re-renders.
- Plurals use a `{ one, other }` entry and `t("inbox.count", { count })`.
- Placeholders use `{name}`. Both languages must use the same placeholders.
- Dates and times use `getLocaleTag()`, for example `date.toLocaleString(getLocaleTag())`.

## Adding a message

1. Pick a key with the file's prefix, for example `inbox.` for `catalog/inbox.ts`. Keys must be unique across all catalog files.
2. Add the English text to `en`. Then add the Turkish text to `tr`.
3. Use `useT()` in the component and replace the literal.

`npx vitest run src/shared/i18n` checks the catalog. It covers matching keys, matching placeholders, plural shapes, and empty values.

## What is not translated

- Prompts sent to agents and Mono system instructions. Translating them would change agent behavior.
- Provider protocol parsing. Claude Code, Codex, and the other CLIs emit English event text, and the parsers match it.
- Developer logs, stack traces, and raw technical error details.
- Product names, provider names, commands, file paths, keyboard shortcuts, and code.
