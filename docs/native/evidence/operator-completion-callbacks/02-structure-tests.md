# Structure and verification audit

Measured all changed Rust files with git show origin/main:<path> and line counts. The callback tests initially grew app_commands/tests.rs from 667 to 1375 lines. That crossed the skill's 1000-line bar without a structural reason. Completion fixtures and tests now live in app_commands/tests/completions.rs, using their parent module's existing authorisation setup and call helper. The parent is 669 lines and the new callback module is 709 lines. No file crosses from below 1000 to above 1000.

Existing giant files receive only registration and lifecycle hooks. shell.rs grows from 13437 to 13446 lines, with callback logic contained in its dedicated module. Moving the whole shell is outside this feature and would add unrelated churn. Core store.rs adds only the module and exported types. The API validator adds the explicit field and Mono rejection at the existing boundary.

The asynchronous launch effect previously transported six positional values, including neighbouring booleans. SessionLaunch now names those fields. The callback scheduler retains one in-flight key per caller/group, and the final dispatch compares the current subscription members and outcomes to the loaded report before consuming it. The state is neither handed to a worker nor exposed through a general self-send bypass.

The tests cover observable grouping, shared labels across turns, delivered label reuse, opt-in validation, actual Mono handler rejection, busy/draft origins, account recovery, failures, UI cancellation, removal, restart, duplicate events and project/self restrictions. Helpers explicitly hold the provider boundary to avoid launching real CLIs in unit tests. The running-app demo separately proves model resumption and user-visible replies.

Two test failures were captured before the account and pending-report fixes: 16 existing callback tests passed and the two new regressions failed. The native script tests and full core/GPUI suites were also run. Final code was checked again after structural extraction; results are in summary.md.

Baseline check limits: cargo fmt reports existing differences only in shell.rs and shell/terminal_panes.rs. Comparing the formatting transformations of origin/main and this branch confirms those differences are unchanged. Each other touched Rust file passes rustfmt using its package edition, 2021 for core and 2024 for GPUI. Strict Clippy reports six pre-existing warnings in unchanged core files, in the nonminimal_bool and collapsible_match categories. The additional run allows only those two categories while keeping -D warnings for everything else. This does not establish that those two categories contain no possible new warnings; direct source review remains part of the evidence.
